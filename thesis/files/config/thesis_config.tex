% Comando di citazione per le fonti giuridiche (leggi, decreti, direttive):
% stampa il campo "usera" del file .bib (tipo di atto, data completa, numero)
% invece della citazione autore-anno/numerica, mantenendo comunque il
% collegamento bibliografico e il backref standard di biblatex.
% Si usa il campo generico "usera" (e non "shorthand") perché "shorthand" è
% un campo riservato di biblatex: se un'entry lo definisce, gli stili
% numerici (incluso "ieee") lo utilizzano al posto del numero progressivo
% come "labelnumber", rompendo la numerazione IEEE e la relativa gabbia di
% impaginazione (hanging indent) della bibliografia. "usera" non ha invece
% alcun significato predefinito per biblatex ed è quindi sicuro da riusare.
% Uso identico a \footcite: \legfootcite[postnote]{chiave-bib}
\DeclareCiteCommand{\legfootcite}[\mkbibfootnote]
  {}
  {\usebibmacro{citeindex}%
   \thefield{usera}%
   \iffieldundef{postnote}
     {}
     {\addcomma\space\printfield{postnote}}}
  {\multicitedelim}
  {\addperiod}

% Ridefinizione di \footcite per le fonti non giuridiche in stile IEEE:
% lo stile "ieee" (biblatex-ieee) definisce di default \footcite senza le
% parentesi quadre che invece usa per \cite nel corpo del testo (assume che
% la nota a piè di pagina renda già evidente il rimando). Qui si vuole che
% SOLO il numero della fonte sia racchiuso tra parentesi quadre, mentre
% l'eventuale postnote (capitolo, paragrafo, pagina) resta fuori dalle
% parentesi, secondo il formato:
%   [3], cap. 4, § 4.2.
% invece di "[3, cap. 4, § 4.2]" o di "3, cap. 4, § 4.2" senza parentesi.
% NOTA DI PORTABILITÀ: "ieee.cbx" (biblatex-ieee) sceglie internamente quale
% variante di stile citazionale caricare per implementare \cite/\footcite
% (tipicamente "numeric-comp", che comprime intervalli di citazioni multiple
% del tipo [3]-[5]); tale variante può differire fra installazioni/versioni
% diverse di biblatex-ieee (ad es. TeX Live vs. MiKTeX), e con essa cambiano
% anche i nomi dei bibmacro interni usati per assemblare la citazione
% (bibmacro come "cite:init"/"cite:comp"/"cite:dump" esistono infatti SOLO
% nella variante "numeric-comp"/"numeric-icomp", non ad esempio in
% "numeric-verb", dove "\footcite" è invece assemblato con un bibmacro
% generico chiamato semplicemente "cite"). Per evitare che questa
% ridefinizione smetta di funzionare a seconda della variante caricata,
% qui non ci si appoggia a NESSUNO di questi bibmacro interni: il numero
% viene stampato direttamente con \printfield{labelnumber} (preceduto dal
% campo, anch'esso opzionale, "labelprefix"), racchiuso in
% \printtext[bibhyperref]{...} per mantenere il collegamento ipertestuale
% e il backref verso la bibliografia. "citeindex", "labelnumber",
% "labelprefix" e il field-format "bibhyperref" sono infatti definiti in
% modo generico in biblatex stesso (non in uno specifico file di stile),
% e sono quindi stabili su qualunque variante/versione di biblatex-ieee.
% Nota: questa versione non comprime in intervalli citazioni multiple nello
% stesso \footcite (es. \footcite{a,b,c}), a differenza della variante
% "numeric-comp": non è un problema per il presente lavoro, dove ogni nota
% a piè di pagina cita di norma una sola fonte per volta.
% NOTA SULL'ORDINE: il numero viene stampato PRIMA della prenote (es.
% "[16] Sono le Sufficient Techniques...") anziché dopo (es. "Sono le
% Sufficient Techniques...[16]."), a differenza della normale convenzione
% editoriale. Questo perché, quando il numero viene stampato DOPO una
% prenote, biblatex lascia uno spazio "differito" (il suo meccanismo
% interno di tracciamento della punteggiatura, legato a \isdot/\space in
% \usebibmacro{prenote}) che \printfield scarica proprio davanti al
% numero, producendo "[ 16]" invece di "[16]" (bug riproducibile sia su
% TeX Live sia su MiKTeX). Stampando il numero per primo, senza alcun
% testo differito prima di esso, il problema non si presenta.
\DeclareCiteCommand{\footcite}[\mkbibfootnote]
  {}
  {\usebibmacro{citeindex}%
   \mbox{\bibopenbracket\printtext[bibhyperref]{\printfield{labelprefix}\printfield{labelnumber}}\bibclosebracket}% \mbox: evita che "[N]" si spezzi su due righe
   \iffieldundef{prenote}{}{\space\printfield{prenote}\isdot}% prenote dopo il numero, con punto finale se mancante
   }
  {\multicitedelim}
  {\usebibmacro{postnote}}

% Sistema di rimando per Acronimi e Glossario
%
% Nel testo esistono tre categorie di termini, descritte in
% preface/.../convenzioni_tipografiche.tex ("Acronimi e abbreviazioni" /
% "Termini del glossario"), ciascuna con un comando e una resa proprie:
%
%  1) ACRONIMI PURI, senza voce di Glossario associata (es. API, LLM,
%     UNI, CEI): comando \acr{label}. Alla prima occorrenza stampa la
%     forma estesa seguita dalla sigla fra parentesi, in nero e SENZA
%     collegamento ipertestuale (l'elenco "Acronimi e abbreviazioni" in
%     fondo al documento non è un rimando a una spiegazione ulteriore
%     come il Glossario, ma un semplice indice): non c'è quindi motivo
%     di colorarlo o di renderlo cliccabile. Alle occorrenze successive
%     stampa solo la sigla, sempre in nero.
%
%  2) VOCI DI GLOSSARIO PURE, senza acronimo associato (es. tranco,
%     luminanza relativa sRGB): comando \gls{label}, sintassi invariata.
%     Alla prima occorrenza è in hyperColor, corsivo, con apice G (v.
%     \glox sopra), collegata alla voce di Glossario. Alle occorrenze
%     successive è in nero, senza corsivo né apice, non collegata.
%
%  3) ACRONIMI CHE HANNO ANCHE una voce di Glossario (es. AGID, WAVE,
%     MAUVE, ciascuno con una voce "<label>-descrizione" nel Glossario):
%     comando \acrg{label}. Alla prima occorrenza stampa la forma estesa
%     seguita dalla sigla fra parentesi E l'apice G, tutto in hyperColor,
%     collegato alla voce di Glossario "<label>-descrizione" (non
%     all'elenco degli Acronimi, che per queste voci non aggiungerebbe
%     nulla alla spiegazione già presente nel Glossario). Alle occorrenze
%     successive stampa solo la sigla, in nero, come gli acronimi puri.
%
% In tutti e tre i casi, dalla seconda occorrenza in poi il termine non è
% più "segnalato": niente colore, niente corsivo/apice, niente link, solo
% testo normale. \acrshort non è più utilizzato: la forma breve delle
% occorrenze successive è ora gestita direttamente da \acr/\acrg.
% ------------------------------------------------------------------

% 1) Acronimi puri (\glsentrylong/\glsentryshort leggono le forme estesa
% e breve direttamente dalla voce "\newacronym", senza mai passare da
% \gls: niente colore, niente link, in nessuna occorrenza). \ifglsused/
% \glsunset sono i comandi standard di "glossaries" per interrogare e
% impostare manualmente lo stato "già incontrato" di una voce.
% \glsadd (senza produrre testo né link) è ciò che normalmente fa \gls
% "dietro le quinte" per segnalare che una voce è stata richiamata nel
% documento, cosicché compaia nell'elenco stampato in fondo (altrimenti,
% bypassando sempre \gls, l'elenco "Acronimi e abbreviazioni" risulterebbe
% vuoto anche per le voci di fatto usate).
\newcommand{\acr}[1]{%
  \ifglsused{#1}%
    {\glsentryshort{#1}}%
    {\glsentrylong{#1}\space(\glsentryshort{#1})\glsadd{#1}\glsunset{#1}}%
}

% 3) Acronimi con voce di Glossario associata: prima occorrenza in
% hyperColor con apice G, collegata a "<label>-descrizione" tramite
% \glshyperlink (rimando manuale a una voce di glossario diversa da
% quella richiamata, con testo personalizzato: non passa da \gls, quindi
% non è soggetto al comportamento automatico "esteso/breve" di
% \newacronym, gestito qui invece "a mano" con lo stesso schema di \acr).
% Occorrenze successive identiche a quelle degli acronimi puri.
% \glshyperlink (a differenza di \gls) non segnala da sé la voce come
% "richiamata" nel documento: \glsadd lo fa esplicitamente per entrambe le
% voci coinvolte, quella di Acronimi (#1, per comparire anche nel relativo
% elenco) e quella di Glossario (#1-descrizione, a cui punta il link).
\newcommand{\acrg}[1]{%
  \ifglsused{#1}%
    {\glsentryshort{#1}}%
    {\glshyperlink[\textcolor{hyperColor}{\glsentrylong{#1}\space(\glsentryshort{#1})}\glox]{#1-descrizione}\glsadd{#1}\glsadd{#1-descrizione}\glsunset{#1}}%
}

% 2) Voci di Glossario pure: \gls{} resta invariato nella sintassi. La
% distinzione fra prima occorrenza e occorrenze successive non richiede
% controlli manuali (a differenza di \acr/\acrg sopra) perché "glossaries"
% la traccia già internamente per ogni voce, tramite \ifglsused: il testo
% del rimando passa comunque sempre da \glstextformat (invocato da \gls
% a ogni occorrenza, prima o successiva, DOPO aver già deciso il testo da
% mostrare ma PRIMA di impostare la voce come "usata"), qui ridefinito per
% applicare rese diverse nei due casi. Il controllo sul tipo (\ifdefstring
% su "main") resta come rete di sicurezza nel caso in cui, per errore,
% \gls venga usato al posto di \acr/\acrg su una voce di tipo "acronym":
% in tal caso ricade nella resa "acronimo puro" (occorrenza normale, mai
% colorata) invece che in quella di Glossario.
% Nota tecnica: \ifglsused{\glslabel} dentro \glstextformat riporta
% correttamente "non ancora usata" anche durante la stessa chiamata che
% marca la voce come usata (la verifica avviene prima di tale
% marcatura) - comportamento confermato con un file di prova minimale
% prima di applicarlo qui.
\renewcommand*{\glstextformat}[1]{%
  \edef\glscurrenttype{\glsentrytype{\glslabel}}%
  \ifglsused{\glslabel}%
    {#1}%
    {\ifdefstring{\glscurrenttype}{main}
       {\textcolor{hyperColor}{\textit{#1}}\glox}
       {#1}%
    }%
}
